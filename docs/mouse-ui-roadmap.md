# 滑鼠操作 UI：長期決策與實作追蹤

建立日期：2026-10-27（Asia/Taipei）。

這份文件是本專案的長期記憶與進度來源，供後續開發與跨對話接續使用。
初始提交只盤點頁面、保存決策並建立 draft PR；後續依使用者指定範圍逐項實作。

## 分支與交付方式

- Repository：`Garrison-code/pokerogue`。
- 目標分支：`develop`。
- 工作分支：`feat/mouse-ui-support`。
- 起點：當次從遠端取得的最新 `develop`，commit `04c230cd564238ed80f39d27ce7120bdfa37b956`。
- 每個尚未合併的階段沿用同一個工作分支與 draft PR，讓使用者逐次檢視。
- 使用者可先將目前已完成進度合入 `develop`；這是階段交付，不代表整份 roadmap 或滑鼠操作 UI 已完成，其他待辦維持 `[ ]`。
- 階段 PR 合併後保留並繼續使用 `feat/mouse-ui-support`；後續開發前先同步合併後的 `develop`，再從此分支另開目標為 `develop` 的 draft PR，不重開已合併的 PR。
- 每完成一個頁面／追蹤項目，就驗證、更新本文件、建立一個 commit 並 push。
- 不把多個已完成頁面累積到最後才一起提交；共用前置工作可獨立成一個明確範圍的 commit。
- 初始規劃 commit 不代表任何頁面的滑鼠操作已完成。
- CI 驗證須包含 REUSE 授權檢查；新增文件也要提供 SPDX 版權與授權標記，不能只檢查 Biome。

## 已確認的方向

- 保留現有鍵盤操作，分階段增加滑鼠操作。
- 新增按鈕、箭頭與互動標示須遵循既有美術風格：優先重用現有像素素材、配色、比例與主題樣式，不引入風格不同的網頁按鈕。
- 點擊不同選項是「選取」；點擊目前選取的選項是「確認」，不是限定時間內的雙擊。
- 滑鼠移入不改變選取。按鈕文字已提供資訊時，不額外新增提示。
- 滾輪不必全面模擬方向鍵；各頁的操作方式在實作該頁前再確認。
- 尚未決定其他頁面要採逐項選取、捲動或數值調整；先前討論過的候選方式不能視為已定案。
- 一般選項／確認選單的滾輪方式已於下節定案；其他多區域頁面仍待各頁開發時處理。

目前版本有部分登入／彈窗點擊、資訊 hover，以及虛擬觸控按鍵。
這些局部支援不代表已完成整頁驗證，也沒有一個現成設定能開啟全遊戲的直接點選。

## 全域決策：右鍵完全沿用既有 CANCEL

本規則適用整份 roadmap 的所有 UI／EX 項目，包含已完成頁面的補強與後續尚未實作頁面。

- 各頁增加滑鼠操作時，只要原本支援鍵盤取消，就將有效範圍內的右鍵直接送入 `UI.processInput(Button.CANCEL)`；不另寫右鍵取消邏輯，也不直接呼叫返回、關閉或取消項目的回呼。
- 右鍵與鍵盤 CANCEL 在相同頁面狀態下具有完全相同的作用與結果，包含游標變化、取消項目、回呼參數、返回層數、音效、失敗結果與 `keepOpen`。CANCEL 若是推進訊息或取消目前選取，右鍵也執行該動作，不一律解讀為返回上一頁。
- 完全沿用既有取消限制、確認／關閉延遲及明確允許的延遲略過設定；不放寬，也不額外增加右鍵專用限制。左鍵專用的選取／確認或提示就緒條件不套用到右鍵。
- 保留直接滑鼠輸入的共通保護：事件先消耗，再檢查目前 handler、啟用狀態、教學及轉場；上層介面攔截右鍵，不得取消背景或穿透到新頁。觸控不走新增的滑鼠路徑。
- 生效區域依各頁已定案規格；UI-01／02／04 為選單框（含列與留白）、UI-03 為訊息框、UI-05 為彈窗本體，UI-07／08／09 為頁面內。UI-05 外側及淡出遮罩仍只阻擋事件，不關閉彈窗。
- 原本沒有 CANCEL 動作或目前禁止取消時，右鍵不得新增返回能力；UI-06 主畫面維持右鍵無作用。其他頁面的實作與範圍仍按項目驗證，不因這項全域決策自動標成完成。
- 後續每頁驗收須對照右鍵與鍵盤 CANCEL 在相同狀態下的結果；各頁文字只補充範圍與既有 CANCEL 的具體作用，不另定一套右鍵語意。

## 已定案：一般選項、確認、選單內子選單與主畫面

對應 UI-01 `OPTION_SELECT`、UI-02 `CONFIRM`、UI-04 `MENU_OPTION_SELECT`、UI-06 `TITLE`；是否完成仍以清單與完成紀錄為準。

- 左鍵點不同項目只選取；點目前項目執行既有確認流程，包含開啟時已預選的項目。
- 滑鼠移入不改變選取；不可選項目不執行回呼。
- 滾輪只在選單內生效，每個垂直 wheel 事件移動一個可選項目，必要時捲動列表。
- 滾輪到首／末項停止，不循環；鍵盤原有循環行為保留。水平滾輪不操作選單。

- 以上四種 UiMode 已啟用共用選單的直接滑鼠操作；MENU 的頁面背景與入口另依 UI-20 規格，AUTO_COMPLETE 仍待辦。
- UI-04 包含資料管理、社群與存檔欄位的子選單；不擴充父頁、檔案選擇或後續介面的操作。
- UI-06 包含繼續、新遊戲、讀取、紀錄及選單入口；只驗證尚未支援的後續頁面能正確開啟，不擴充其操作。主畫面保留既有取消限制，右鍵不取消。

## 已定案：新遊戲的寶可夢選擇頁

對應 `STARTER_SELECT`，主要程式為 `src/ui/handlers/starter-select-ui-handler.ts`。
目前格子每列 9 隻，最多顯示 9 列，並有篩選列、已選隊伍與開始按鈕。

| 位置／動作 | 決定的行為 |
| --- | --- |
| 滑鼠在寶可夢格子區內使用滾輪 | 上下捲動列表，以列為單位；不是逐隻切換選取 |
| 點擊不同寶可夢 | 選取該寶可夢並顯示資料 |
| 再點目前選取的寶可夢 | 執行既有確認流程，開啟寶可夢操作選單，例如加入隊伍；不直接略過既有選單 |
| 篩選下拉選單已開啟 | 滾輪只操作下拉選單，不同時捲動背後的寶可夢列表 |
| 已選隊伍、開始按鈕 | 以點擊操作；不讓格子區的滾輪跳到這些區域 |
| 列表捲動後 | 記住選取的寶可夢身分，不把原格子內新出現的寶可夢誤當成已選取 |
| 原本選取的寶可夢已捲出畫面 | 點擊新出現的另一隻時，必須先選取，不能直接確認 |

原則是「滑鼠點選位置、滾輪瀏覽列表」，不需要滾輪同時表達上下左右。
本頁子區域的操作已確認如下：

- 格子包含圖示、文字與留白；未捕獲物種仍可選取查看，確認沿用既有錯誤。垂直滾輪每事件捲動一列，到邊界停止，不改變其他區域焦點；水平滾輪不操作，捲軸不新增拖曳。
- 格子選取以物種身分保存；捲出畫面保留資料、隱藏游標，捲回恢復。篩選／排序後重新對應身分，被篩除時清除格子選取與過期資料，下一次點擊先選取。
- 點篩選標籤直接開啟／收起下拉，點其他標籤直接切換；下拉選項採先選取、再點目前項目才執行既有 ACTION。多選、全選、狀態循環與排序方向保持原有規則，HYBRID 世代篩選保留隨游標更新結果的既有行為。
- 下拉內垂直滾輪每事件移動一個選項，到邊界停止，不執行 ACTION；下拉展開時背景格子滾輪只消耗事件。左鍵點背景只收起下拉，同一次點擊不選取或確認背景。
- 已選隊員、隨機與開始皆採兩階段點擊；鍵盤已選取時第一次點擊即可確認。格子與隊伍是不同選取區域，即使同物種也須先切換選取；空隊伍位置不操作。
- 隨機保留篩選、費用、挑戰、避免重複及六隻上限；載入中不重複加入。開始保留空隊伍錯誤、挑戰檢查與確認選單，不略過原流程。
- 點可見的異色、形態、性別、特性、性格、太晶說明圖示／文字，執行對應既有循環按鍵一次；保留解鎖限制與目前寶可夢，不新增按鈕或提示。篩選說明沿用 STATS 入口；隱藏說明不可操作。尚無鍵盤／手把輸入紀錄時，先顯示既有鍵盤圖示與說明，提供滑鼠入口。
- IV、招式、被動、糖果、費用及其他寶可夢操作透過既有操作選單處理。重新命名、圖鑑詳細頁的直接滑鼠操作不在 UI-09 範圍，按後續對應項目處理。
- 頁面內右鍵直接送入既有 CANCEL，不先選取點擊位置；完全沿用當前狀態下的下拉關閉、篩選重設、IV 退出、最後隊員移除及離開流程與限制，不另定右鍵語意。
- 事件先消耗，再檢查目前 handler、教學與轉場；上層介面阻擋背景。移入不選取，中鍵與觸控不啟用新增操作。清理互動區域與監聽，過期素材／隨機載入不得更新新選取或重開的頁面。
- EX-01 保持待辦；教學與沿用教學輸入機制的頁內提示仍使用既有鍵盤／手把操作，不宣稱新玩家已可全程使用滑鼠。

## 清單如何使用

- 下列 phase 是實作階段，不是遊戲內的戰鬥 Phase。
- 依 phase，再依清單順序推進；先完成共用入口，再打通新遊戲、戰鬥與戰後獎勵。
- `[ ]` 表示尚未完成；正在開發仍保持 `[ ]`，可在該項後註記進度。
- `[x]` 才表示 done：已完成該項範圍、做過適當驗證，且會隨同一個 commit 推送。
- 每完成一項，在「完成紀錄」補上項目 ID、日期、驗證結果與 commit 識別。
  為避免 commit 自我引用，可使用唯一 commit subject，或在後續更新補上 SHA。
- 完成驗證須涵蓋相關滑鼠操作與現有鍵盤流程；有版面差異時檢查 default／legacy 主題。
  具體驗證方法隨該頁實作選擇，未驗證不得宣稱通過。
- 已有滑鼠操作的頁面以補齊或驗證為主；純狀態頁若確認無需互動，可記錄理由後標 done。
- 未在「已定案」段落記錄的項目只定義盤點範圍與順序，尚未決定互動細節。

## 盤點依據與範圍

- 以 `src/enums/ui-mode.ts` 的全部 **48 個 UiMode**，以及 `src/ui/ui.ts` 的 handler 註冊為基準。
- 每個 UiMode 恰有一個主要 UI 項目；另列 **6 個未獨立註冊的介面／覆蓋層項目**，共 **54 個追蹤項目**。
- 共用元件位於 `src/ui/containers/`，例如 `filter-bar.ts`、`dropdown.ts`、`filter-text.ts`、`scroll-bar.ts`、`tab-menu.ts`；它們跟隨使用它們的頁面驗證，不另當成新頁面。
- `UiHandler`、`AwaitableUiHandler`、`MessageUiHandler`、`ModalUiHandler`、`FormModalUiHandler` 等基底類別是共用實作，不重複計為獨立頁面。
- 性別／模式／生態域選擇等動態選單，以及捕捉、換人、學招、遊戲結束等提示，由對應的共用選單、確認、訊息或詳細頁項目涵蓋；不因沒有專屬 UiMode 而漏掉。
- 鍵盤輸入文字、設定鍵盤／手把綁定等操作仍可需要原本裝置；本專案的目標是讓 UI 導航與選項操作支援滑鼠。
- 本清單依上述 develop 起點建立；後續若 develop 新增頁面，須先補進清單再實作。
