# 滑鼠操作 UI：長期決策與實作追蹤

建立日期：2026-10-27（Asia/Taipei）。

這份文件是本專案的長期記憶與進度來源，供後續開發與跨對話接續使用。
初始提交只盤點頁面、保存決策並建立 draft PR；後續依使用者指定範圍逐項實作。

## 分支與交付方式

- Repository：`Garrison-code/pokerogue`。
- 目標分支：`develop`。
- 工作分支：`feat/mouse-ui-support`。
- 起點：當次從遠端取得的最新 `develop`，commit `04c230cd564238ed80f39d27ce7120bdfa37b956`。
- 後續沿用同一個工作分支與 draft PR，讓使用者逐次檢視。
- 每完成一個頁面／追蹤項目，就驗證、更新本文件、建立一個 commit 並 push。
- 不把多個已完成頁面累積到最後才一起提交；共用前置工作可獨立成一個明確範圍的 commit。
- 初始規劃 commit 不代表任何頁面的滑鼠操作已完成。

## 已確認的方向

- 保留現有鍵盤操作，分階段增加滑鼠操作。
- 點擊不同選項是「選取」；點擊目前選取的選項是「確認」，不是限定時間內的雙擊。
- 滑鼠移入不改變選取。按鈕文字已提供資訊時，不額外新增提示。
- 滾輪不必全面模擬方向鍵；各頁的操作方式在實作該頁前再確認。
- 尚未決定其他頁面要採逐項選取、捲動或數值調整；先前討論過的候選方式不能視為已定案。
- 一般選項／確認選單的滾輪方式已於下節定案；其他多區域頁面仍待各頁開發時處理。

目前版本有部分登入／彈窗點擊、資訊 hover，以及虛擬觸控按鍵。
這些局部支援不代表已完成整頁驗證，也沒有一個現成設定能開啟全遊戲的直接點選。

## 已定案：一般選項、確認與選單內子選單

對應 UI-01 `OPTION_SELECT`、UI-02 `CONFIRM`、UI-04 `MENU_OPTION_SELECT`；是否完成仍以清單與完成紀錄為準。

- 左鍵點不同項目只選取；點目前項目執行既有確認流程，包含開啟時已預選的項目。
- 滑鼠移入不改變選取；不可選項目不執行回呼。
- 滾輪只在選單內生效，每個垂直 wheel 事件移動一個可選項目，必要時捲動列表。
- 滾輪到首／末項停止，不循環；鍵盤原有循環行為保留。水平滾輪不操作選單。
- 選單外點擊及右鍵不觸發操作；取消使用既有取消項目或原本裝置的取消鍵。
- 保留確認延遲、取消限制、回呼結果、音效與 `keepOpen` 行為；轉場、教學及上層介面阻擋背景選單輸入。
- 目前僅對以上三種 UiMode 啟用共用選單的直接滑鼠操作，其他繼承相同基底的頁面仍按清單順序處理。
- UI-04 包含資料管理、社群與存檔欄位的子選單；不擴充父頁、檔案選擇或後續介面的操作。

## 已定案：訊息／對話推進

對應 UI-03 `MESSAGE`，不自動擴及其他繼承 `MessageUiHandler` 的頁面或 EX-01 教學。

- 下方整個訊息框接受左鍵點擊，包含文字、留白與提示箭頭；名字框上方及戰鬥場景不屬於點擊範圍。
- 僅在等待確認時走既有 ACTION 流程；逐字顯示、提示延遲與自動訊息不因點擊補完或提前結束。
- 每次點擊只推進一頁／一個階段，包含能力值與 IV 提示；保留回呼延遲與音效。
- 右鍵、中鍵、移入與滾輪不操作訊息；觸控沿用既有路徑。
- 轉場、教學與上層介面阻擋背景訊息輸入；事件消耗避免點擊穿透新頁或新選單。

## 已定案：新遊戲的寶可夢選擇頁

對應 `STARTER_SELECT`，主要程式為 `src/ui/handlers/starter-select-ui-handler.ts`。
目前格子每列 9 隻，最多顯示 9 列，並有篩選列、已選隊伍與開始按鈕。

| 位置／動作 | 決定的行為 |
| --- | --- |
| 滑鼠在寶可夢格子區內使用滾輪 | 上下捲動列表，以列為單位；不是逐隻切換選取 |
| 點擊不同寶可夢 | 選取該寶可夢並顯示資料 |
| 再點目前選取的寶可夢 | 執行既有確認流程，開啟寶可夢操作選單，例如加入隊伍；不直接略過既有選單 |
| 篩選下拉選單已開啟 | 滾輪只操作下拉選單，不同時捲動背後的寶可夢列表 |
| 已選隊伍、開始按鈕 | 以點擊操作；不讓格子區的滾輪跳到這些區域 |
| 列表捲動後 | 記住選取的寶可夢身分，不把原格子內新出現的寶可夢誤當成已選取 |
| 原本選取的寶可夢已捲出畫面 | 點擊新出現的另一隻時，必須先選取，不能直接確認 |

原則是「滑鼠點選位置、滾輪瀏覽列表」，不需要滾輪同時表達上下左右。
篩選條件、形態／性別／異色等切換、隊伍操作及開始流程，都屬於這頁的實作範圍；
這些子區域尚未逐項設計，不在本次擴充細節。

## 清單如何使用

- 下列 phase 是實作階段，不是遊戲內的戰鬥 Phase。
- 依 phase，再依清單順序推進；先完成共用入口，再打通新遊戲、戰鬥與戰後獎勵。
- `[ ]` 表示尚未完成；正在開發仍保持 `[ ]`，可在該項後註記進度。
- `[x]` 才表示 done：已完成該項範圍、做過適當驗證，且會隨同一個 commit 推送。
- 每完成一項，在「完成紀錄」補上項目 ID、日期、驗證結果與 commit 識別。
  為避免 commit 自我引用，可使用唯一 commit subject，或在後續更新補上 SHA。
- 完成驗證須涵蓋相關滑鼠操作與現有鍵盤流程；有版面差異時檢查 default／legacy 主題。
  具體驗證方法隨該頁實作選擇，未驗證不得宣稱通過。
- 已有滑鼠操作的頁面以補齊或驗證為主；純狀態頁若確認無需互動，可記錄理由後標 done。
- 未在「已定案」段落記錄的項目只定義盤點範圍與順序，尚未決定互動細節。

## 盤點依據與範圍

- 以 `src/enums/ui-mode.ts` 的全部 **48 個 UiMode**，以及 `src/ui/ui.ts` 的 handler 註冊為基準。
- 每個 UiMode 恰有一個主要 UI 項目；另列 **6 個未獨立註冊的介面／覆蓋層項目**，共 **54 個追蹤項目**。
- 共用元件位於 `src/ui/containers/`，例如 `filter-bar.ts`、`dropdown.ts`、`filter-text.ts`、`scroll-bar.ts`、`tab-menu.ts`；它們跟隨使用它們的頁面驗證，不另當成新頁面。
- `UiHandler`、`AwaitableUiHandler`、`MessageUiHandler`、`ModalUiHandler`、`FormModalUiHandler` 等基底類別是共用實作，不重複計為獨立頁面。
- 性別／模式／生態域選擇等動態選單，以及捕捉、換人、學招、遊戲結束等提示，由對應的共用選單、確認、訊息或詳細頁項目涵蓋；不因沒有專屬 UiMode 而漏掉。
- 鍵盤輸入文字、設定鍵盤／手把綁定等操作仍可需要原本裝置；本專案的目標是讓 UI 導航與選項操作支援滑鼠。
- 本清單依上述 develop 起點建立；後續若 develop 新增頁面，須先補進清單再實作。
